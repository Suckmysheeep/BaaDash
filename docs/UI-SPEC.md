# BaaDash UI 规范

适用版本：v0.3.0 起。适用范围：桌面主窗口、独立下载窗口，以及后续新增页面。目标是安静、紧凑、中文优先，以下载任务为中心。

## 功能归属与信息层级

新增功能先确定用户目的、归属页面、默认状态、出现时机、错误反馈，再写界面。不能因为某页已有空间，就把新字段追加进去。

| 设置分类 | 内容 |
| --- | --- |
| 常规 | 托盘、通知、独立进度窗口、剪贴板监视 |
| 外观 | 主题、界面大小 |
| 下载与队列 | 目录、分类、连接数、同时下载数、限速、做种 |
| 网络 | 系统/手动代理；本地 IP 绑定放入高级网络选项 |
| 自动化 | 定时队列、一次性完成动作 |
| 浏览器集成 | 安装、连接、浏览器下载确认与扩展设置入口 |
| 关于 | 版本、检查更新、日志和项目链接 |

SHA-256 属于单个下载任务，不属于全局设置。两个新建下载入口必须使用同一个 `advanced.ts` 组件：文件信息获取成功后才显示“高级选项”；默认折叠、文件校验默认关闭，开启后才显示 SHA-256 输入框。不启用时不提交校验值。新建任务、取消任务或修改来源后清理旧的校验状态。

## 图标

- 应用功能图标统一经 `app/ui/src/icons.ts` 映射，使用 Kubai Icons v0.5.0 的静态 SVG 单色适配。资源按需打包，禁止运行时从 CDN 加载。
- 功能图标与 BaaDash 羊头品牌标识分开。应用图标、托盘品牌、安装器标识继续使用 BaaDash 自有素材。
- 导航 24px，普通操作 16–20px。文件类型图标可用 24–28px。所有图标需在实际大小下检查，不能依赖放大截图判断。
- 图标只辅助识别；按钮必须有可理解的文字或可访问名称。图片图标设置空 alt/aria-hidden，禁止重复朗读。
- 单色适配使用 currentColor 实色轮廓和 9–20% 次级填充，去除阴影，重要符号不可依赖浅色填充识别；展开/收起采用清晰的几何控件符号。默认静态，不让密集列表同时播放动效；未来动效须响应 prefers-reduced-motion。
- 保留 `public/icons/kubai/LICENSE`，新增图标时更新映射和来源说明。
- 新增图标先放入该目录、更新 `tools/ui/icon-map.json`，再运行 `node tools/ui/build-icons.mjs`。生成后的 `icons.ts` 随提交保存；生产构建检查生成结果，禁止手工修改生成文件。

## 表单与布局

- 普通输入和选择控件统一使用 `.form-input`、`.form-select`。最小高度 36px，8px 圆角，水平内边距 11px，1px 细边框；禁用浏览器默认灰底直角输入框直接进入产品。
- 标签在输入框上方；说明在下方，12px、1.6 行高。占位符只给例子，不代替标签。
- 聚焦显示主题色细边及柔和焦点环。错误就近显示，设置 aria-invalid 和可访问错误提示，保留用户输入。
- 设置行最小高度 66px，16px 水平内边距。左侧标题/说明，右侧控件；长说明允许换行。不要挤成一行截断关键解释。
- 主题、常见枚举用现有分段控件；连续的界面缩放用滑杆和百分比；开关用统一 switch；地址用文本框；开始时间启用后才显示日期控件。
- 手动代理仅在选择“手动代理”后显示地址；本地 IP 默认留空，收入“高级网络选项”。高级不是杂物间，仍需有明确领域归属。
- 高级折叠区使用 `.advanced-panel`，单次任务校验再用一个显式启用开关。展开不应自动启用功能。
- 主要按钮只表达当前阶段的下一步。取消、稍后和辅助入口保持低强调。

## 颜色与字体

- 使用 styles.css 中已有的 text、muted、panel、border、accent、red 等语义变量，不能为新功能随意写一套灰色。
- 主题色用于选中、进度、焦点；红色用于错误和破坏性操作。图标沿用统一单色语义，禁止给每个新设置随意分配鲜艳颜色。
- 中文沿用内置 Noto Sans SC。哈希等机器值才用等宽字体。SHA-256 不作为默认可见的功能标题。

## 窗口、状态与可访问性

- 设置导航固定可见，内容区独立滚动，关闭和保存入口不随内容消失。
- 独立下载窗口根据内容调整高度；高级内容展开后必须完整可达，必要时在内容区滚动。
- 不只测试成功状态：空白、加载、无效链接、长中文名称、校验错误、保存失败、取消恢复都属于验收范围。
- 可用键盘操作折叠区、开关、表单和按钮。不能移除控件焦点提示；不能让收起的隐藏字段阻止普通下载。

## 视觉验收与维护

1. `npm run build --prefix app`：类型和生产构建。
2. `npm run test --prefix tools/ui`：交互、布局、扩展和官网回归。
3. `node tools/ui/v030-check.mjs`：设置归属、校验默认隐藏、共享交互与图标资源检查，并生成深浅色截图。
4. 本地 HTTP 预览 `tools/ui/components.html`：查看同一套输入、选择、折叠、焦点和错误组件；该页面需先构建 app。
5. 检查真实尺寸的浅色/深色界面，以及 820px 主窗口、552px 独立下载窗口。截图审核比“构建通过”多一步，不可省略。
6. 改界面后同步 README/官网中受影响的截图和描述，再运行 `node tools/site/build.mjs`。

后续改动可调整规范，但实现和规范必须一起更新。不能用“新增功能”作为绕过分类和组件样式的理由。
