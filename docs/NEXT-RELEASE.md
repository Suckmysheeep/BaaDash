# 下一版规划：图标体系与自定义强调色

记录日期：2026-11-11。仅记录需求，等待维护者恢复额度后明确启动；不据此自动实施或发布。

## 实机反馈

- 维护者确认 v0.3.0 的设置分类、表单及整体 UI 质感有明显改善，应保留这些成果。
- Kubai 图标即使经过单色适配，实机效果仍不理想。下一版应替换，不继续以 Kubai 为基础打磨。

## 图标方向

- 静态图标使用 Lucide；适合交互反馈的少量入口结合 lucide-animated。
- 用户指定参考：https://lucide-animated.com/ 。尚未核实其 API、许可、依赖及与当前原生 TypeScript/Vite 界面的兼容性，开工时先核对官方资料。
- 先在真实的 16/20/24px 尺寸、深浅色主题和实机中比较线宽、对比度、对齐与视觉占位，再统一替换。
- 密集下载列表及普通辅助操作优先静态；主要入口可在悬停、键盘聚焦或明确状态变化时短暂运动。具体入口清单先结合界面规划。
- 遵守减少动态效果偏好，不持续循环或使整页同时运动；不为图标动效直接重写整套 UI 或盲目迁移框架。
- 保留统一图标接口；替换完成后清理不再使用的 Kubai 资源、生成脚本和相应说明，并更新 UI 规范与截图。
- BaaDash 自有品牌图标不在本次反馈的替换范围内。

## 自定义强调色候选功能

- 用户希望能修改界面色调，自定义重点功能使用的强调色。
- 先明确可调范围：推荐色板/自选颜色、选中项、进度、焦点及主要操作的应用关系，避免直接开放所有语义色。
- 设计浅色和深色下的颜色派生与对比度保护；错误、警告、成功等状态仍应清楚可辨。
- 考虑实时预览、取消恢复、恢复默认、持久化及主窗口与下载窗口同步。
- 归入“外观”，使用已有表单与渐进展示规范，不向下载、网络等无关页面追加控件。

2. 给出图标静态/动态分配、自定义强调色范围及实际界面样例，结合维护者意见确定范围。
3. 下一版暂按 v0.3.1 候选规划；若最终范围超出修补版本，由维护者与 agent 再确定版本号。
4. 实施后更新规范、测试、截图、CHANGELOG 和官网，完整验证实机效果；不要只以浏览器放大截图或编译通过验收。
